# passlib 1.7.4's bcrypt backend probes bcrypt.__about__.__version__ at import
# time to detect the installed bcrypt release. That attribute was removed in
# bcrypt 4.1.0 (bcrypt dropped its internal __about__ metadata module), which
# makes passlib's probe raise AttributeError, fall back to a broken detection
# path, and then mis-handle bcrypt's 72-byte password-length check — surfacing
# as "ValueError: password cannot be longer than 72 bytes" even for short
# passwords. bcrypt==4.0.1 is the last release that still exposes
# __about__.__version__, so pinning it here (rather than letting the
# passlib[bcrypt] extra resolve to whatever bcrypt is newest) restores the
# code path passlib 1.7.4 actually expects, with no change to hashing
# behavior, password handling, or truncation.
